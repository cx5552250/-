## 核心模块说明

### 1. crawler.py - 资讯爬虫模块

**职责：** 从多个资讯源抓取原始新闻数据

**关键功能：**
- 支持多种资讯源类型（网页、RSS等）
- 针对不同网站的定制化解析规则
- 通用网页解析fallback机制
- 异常处理和重试机制

**技术栈：**
- `requests`: HTTP请求库
- `BeautifulSoup4`: HTML解析
- `lxml`: 高性能XML/HTML解析器

**扩展性：**
添加新资讯源只需在`config.py`中配置，并在`crawler.py`中添加对应的解析方法。

### 2. processor.py - 资讯处理模块

**职责：** 对原始新闻进行清洗、去重、评分和排序

**核心算法：**

#### 相关度评分算法
```python
score = 关键词匹配分 + 时间新鲜度分

关键词匹配分：
- 标题中出现关键词: +15分/词
- 摘要中出现关键词: +8分/词

时间新鲜度分：
- 24小时内发布: +20分
- 48小时内发布: +10分
```

#### 去重算法
- 基于标题的MD5哈希值
- 标准化处理（去除标点、转小写）
- 确保相同内容只保留一条

**可调整参数：**
- `KEYWORDS`: 行业关键词列表
- `MAX_NEWS_COUNT`: 最大推送条数

### 3. wechat_bot.py - 企业微信推送模块

**职责：** 将格式化后的资讯推送到企业微信

**支持的消息类型：**
- Markdown格式（推荐，支持富文本）
- 纯文本格式（备用方案）

**API接口：**
- 企业微信机器人Webhook API
- POST请求，JSON格式

**安全性：**
- Webhook URL通过GitHub Secrets管理
- 不在代码中硬编码敏感信息

### 4. config.py - 配置文件

**集中管理所有配置项：**
- 企业微信Webhook URL
- 资讯源列表
- 行业关键词
- 推送数量限制
- 调试模式开关

**优势：**
- 修改配置无需改动代码逻辑
- 便于不同环境的配置管理

## 数据流转过程

```
原始网页 
  ↓ [爬虫抓取]
原始新闻列表 (可能100+条，包含无关内容)
  ↓ [去重处理]
去重后新闻列表 (可能80条)
  ↓ [关键词筛选]
相关新闻资讯 (可能30条)
  ↓ [热度评分排序]
排序后的相关资讯 (按分数从高到低)
  ↓ [取Top N]
最终推送列表 (10条)
  ↓ [格式化]
Markdown文本
  ↓ [微信推送]
您的手机收到消息 ✅
```

## GitHub Actions工作流

### 触发条件
1. **定时触发**: 每天UTC 0点（北京时间8点）
2. **手动触发**: 可随时在Actions页面手动运行

### 执行步骤
```yaml
1. 检出代码 (checkout)
2. 设置Python 3.10环境
3. 安装依赖包 (pip install)
4. 注入Webhook密钥 (从Secrets读取)
5. 执行main.py主程序
6. 失败时输出错误日志
```

### 优势
- ✅ 完全免费（GitHub免费额度足够）
- ✅ 无需维护服务器
- ✅ 高可用性（GitHub基础设施）
- ✅ 自动日志记录

## 技术选型理由

| 技术 | 选择理由 |
|------|---------|
| Python | 生态丰富，开发效率高，适合爬虫和数据处理 |
| BeautifulSoup | 简单易用，容错性强，适合不规则HTML |
| GitHub Actions | 免费、稳定、无需运维，适合定时任务 |
| 企业微信 | 个人可用，API简单，消息到达率高 |
| Markdown | 支持富文本，可读性好，企业微信原生支持 |

## 安全考虑

1. **密钥管理**: Webhook URL存储在GitHub Secrets，不会暴露在代码中
2. **访问控制**: 只有仓库所有者可以查看Secrets
3. **HTTPS**: 所有网络通信使用加密连接
4. **输入验证**: 对用户配置进行基本验证

## 故障处理

### 常见故障及解决方案

| 故障 | 原因 | 解决方案 |
|------|------|---------|
| 推送失败 | Webhook URL错误 | 检查Secrets配置 |
| 抓取为空 | 网站结构变化 | 更新解析规则 |
| 评分不准 | 关键词不足 | 补充关键词列表 |
| 执行超时 | 网络问题 | 增加timeout或重试 |
